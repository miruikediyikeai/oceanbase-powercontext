# 数据流与设计

## 一次复习

浏览器读取 `/api/workspace` → 应用为服务端固定的学习者解析稳定 Scope → 从 PowerContext `/v1/memory/entries/list` 读取当前卡片与偏好 → 复习规则只选择到期卡片，优先最近自评为未记住的卡片 → 浏览器展示问题、答案和来源。

用户自评时，浏览器提交卡片 ID、等级和当前 `entry_version_id`。应用读取最新记录，比较版本，计算下一次复习时间，再向 `/v1/memory/entries/revise` 提交精确 citation。只有服务确认后才显示已保存。重新打开浏览器或重启应用会再次读取同一 Scope；应用不靠浏览器缓存恢复进度。

## 记录与身份

| 记录 | 作用 | 身份 |
| --- | --- | --- |
| Scope | 单个学习空间 | PowerContext 返回的 `scope_id`，由稳定 idempotency key 恢复 |
| `recall_card_v1` | 原始问题、答案、来源和当前学习状态 | 导入数据的稳定卡片 ID + PowerContext entry identity |
| `recall_preferences_v1` | 称呼和每轮卡片数 | 每个学习 Scope 唯一一条偏好记录 |
| citation | 可核对的历史证据 | Memory revision、entry ID 与 entry version ID |

每个卡片状态包含 `schema_version: 1`。更新保留卡片 ID，旧版本由 PowerContext 保管。计划和统计均为只读派生数据，不作为新的权威状态保存。导出的证据是一个时间点的读数，后续状态以 PowerContext 为准。

## 错误、并发和恢复

应用使用单进程锁串行处理一个学习空间的读改写。浏览器版本过期返回 409；底层服务返回版本冲突时也返回 409。无法连接服务时显示不可用，不切换为本地假记忆。连接错误不会自动重试写操作，用户先刷新核对结果。

卡片导入先验证所有输入和已存身份，再逐条写入。后续条目失败时已保存的条目不回滚；相同文件重新导入会跳过它们。未知 schema、重复卡片身份或偏好记录冲突时拒绝继续写入。首个空空间写入和跨进程并发未提供分布式唯一约束，因此该原型限定一个应用进程负责一个学习者。

## 范围

采用显式 Memory 读写，不依赖自动提取、语义检索、推理服务或 seekdb。单次操作读取全部当前 Memory，最多支持 100 张卡片；尚未测量更大规模成本。复习规则是启发式，用户自行判断掌握程度，累计复习数不等于有效学习时长或学习效果。
